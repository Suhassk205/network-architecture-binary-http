# Annotated complete request and response

Generated by `python3 tools/capture.py` from the actual client and server on a loopback TCP socket. The sample file is `www/hello.txt`. The connection uses an ephemeral listening port, while the request host header is fixed to `localhost:9000` for reproducibility; the protocol does not require the host header to match the listening port. The temporary fixture modification time is fixed to 1 January 2026 UTC.

The complete request contains **59 bytes**; the complete response contains **139 bytes**. Raw wire bytes are in `request.bin` and `response.bin`; `session.hex` is the verbose frame capture. No TCP/IP headers are included. Hex offsets reset for each frame.

The response has one metadata frame followed by one final DATA frame. END on the request and final response DATA marks message completion; the server leaves the TCP connection open. The client closes it after this exchange. The persistence tests separately issue multiple requests on one socket.

## Header compression example

The name `content-length` would take 14 literal name bytes, plus its one-byte name length. Its fixed ID `05` replaces those name bytes; its value remains length-prefixed. All ten assigned names are used across the request and successful response. Unknown literal names use ID 00 followed by their name length and bytes, as specified in section 4.

## Independent verification

The annotation walks the captured bytes using an independent `struct` parser and asserts that every payload byte is consumed. `python3 tools/capture.py --check` regenerates the exchange and requires exact byte equality with all four checked-in artifacts. The protocol tests separately exercise unknown-frame skipping before and between response frames, and recovery after malformed requests.
